# StarSign role matrix

Originally generated by `keycloak/generate_authz.py` from the AndroMDA UML model in starsign-mda; maintained by hand since the port to starsign-api.

## Roles

Roles are hierarchical: a role has everything the roles it includes have (Keycloak composite roles).

| Role | Abbrev. | Includes | Description |
|---|---|---|---|
| `STARSIGN_USER` | SU | `PORTAL_USER` (starsign-portal client role) | Base role of every organisation user: signs in to the portal, own profile, signs documents assigned to them |
| `ORGANISATION_USER` | OU | `STARSIGN_USER` | Uploads documents, prepares and sends signing workflows (own documents) |
| `SIGNING_OFFICER` | SO | `STARSIGN_USER` | Internal signatory: reads the documents and workflows they take part in |
| `DOCUMENT_MANAGER` | DM | `ORGANISATION_USER` | Manages every document, workflow and template of the organisation |
| `AUDITOR` | AUD | `STARSIGN_USER` | Read-only access to the organisation's documents, workflows, evidence and audit trail |
| `ORGANISATION_ADMIN` | OA | `DOCUMENT_MANAGER`, `SIGNING_OFFICER`, `AUDITOR` | Administers the organisation: users, roles, policies, branding, subscription |
| `PLATFORM_ADMIN` | PA | `PORTAL_USER` (starsign-portal client role) | Platform administration: organisations, plans, providers, storage, security policy |
| `DEVELOPER` | DEV | `PLATFORM_ADMIN`, `ORGANISATION_ADMIN` | Developer / tester: platform and organisation administration with one account (never assign in production) |

## Scopes

| Scope | Meaning |
|---|---|
| `self` | Act on the caller's own data (my profile, my organisation, my notifications) |
| `view` | Read a single record |
| `list` | List, page or search records |
| `edit` | Create or update a record, prepare a workflow |
| `delete` | Remove, archive or soft-delete a record |
| `initiate` | Send a workflow for signing, renew, amend or resend invitations |
| `cancel` | Cancel or recall a workflow |
| `sign` | Sign or decline as an internal signatory |
| `verify` | Verify document integrity or the audit hash chain |
| `export` | Download documents and evidence, export reports and audit trails |
| `manage` | Administer user accounts, sessions, invitations and role assignments |
| `configure` | Change organisation policies, notification settings and branding |
| `administer` | Platform administration across tenants (no access to document contents) |

Keycloak scopes are named `<resource>:<action>`; PermissionService turns each granted one into the authority `SCOPE_<resource>:<action>`, e.g. `@PreAuthorize("hasAuthority('SCOPE_documents:view')")` (Pattern B). Pattern A endpoints also carry `@RequiresPermission`: `-own` holders pass only when they own the record.

Owner-scoped roles (ORGANISATION_USER, SIGNING_OFFICER) are granted `<scope>-own` instead of `<scope>` on `documents`, `workflows` (shown as "own:"): the service limits them to records they own or sign.

`self` is granted to every authenticated user and is left out of the table. Tenant isolation is enforced by the API for every role; platform roles carry no tenant and never see document contents.
